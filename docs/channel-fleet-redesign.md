# 频道（Channel）界面重构方案

状态：设计已敲定，未开始实现
日期：2026-11-07
范围：频道网格、新建频道、分组、设置页；不改变底层 profile / brain 数据模型

## 0. 已敲定规则

- 用户界面统一用「频道」，不出现 profile / 档案。
- 一张卡片 = 一个频道。
- 未分组是系统收件箱，不是普通分组：没有「更多」菜单，只能通过末尾「＋」卡片新建。
- 普通分组有完整「更多」菜单，第一项是「新建频道」。
- 新建频道走草稿模式，点保存才落盘；返回不保存则什么都不留下。
- 新建频道不自动切换当前频道。
- 手机端底部只保留「回到消息」；桌面端不显示底部横条，用左上角关闭。
- 设置页不再有「档案」tab，只保留通用配置；频道编辑独立为「频道设置」页面。
- 「＋」卡片不参与拖拽、搜索和频道计数；未分组为空时也显示。
- 切换当前频道后，消息流定位到该频道历史的最底部。

## 1. 术语

用户界面统一使用“频道”，不再出现 profile / 档案。

| 界面词 | 含义 | 内部对象 |
| --- | --- | --- |
| 频道 | 一张卡片 / 一个独立助手身份 | `Profile` |
| 分组 | 用户手动创建的频道分组 | `ProfileGroup` |
| 未分组 | 系统收件箱，不属于用户分组 | `groupId == null` |
| 新建频道 | 新建一个频道 | 新建 `Profile` |
| 频道设置 | 新建或编辑频道配置的页面 | 新建页 / `ProfileEditor` |
| 当前频道 | 当前聚焦、会播放声音的频道 | `focusedProfileId` |
| 回到消息 | 从频道网格返回消息流 | 折叠网格 |

## 2. 频道网格

- 一张卡片 = 一个频道。
- 分组标题下按网格排列该组的频道。
- 频道卡片保持现有交互边界：
  - 卡片主体只切换当前频道；
  - 右上角开关只打开/关闭后台接收，不切换焦点；
  - 右下角菜单：编辑频道、移动到分组。
- 搜索、分组筛选、拖拽排序保留。
- 拖拽仍然支持：同组内重排、拖到其他组换组、长按组标题调整组顺序。
- 消息气泡文本支持选择与复制：
  - 手机端长按消息文本进入选择，使用系统选择手柄和上下文菜单；
  - 桌面端支持拖选、右键上下文菜单复制；
  - 选择消息文本不能破坏消息流的滚动、频道切换和历史加载。

## 3. 分组与「未分组」

### 普通分组

- 用户手动创建。
- 「更多」菜单：
  1. 新建频道
  2. 重命名
  3. 上移
  4. 下移
  5. 删除
- 删除分组后，成员回到「未分组」，分组本身消失。

### 未分组

- 不是用户分组，不建 `ProfileGroup` 记录，只是 `groupId == null` 的频道集合。
- 界面上仍然有「未分组」section 和筛选 chip。
- 没有「更多」菜单，不能重命名、排序或删除。
- 新建入口只有 section 末尾固定的「＋」卡片。
- 分组计数不包含「＋」卡片。

## 4. 新建频道

### 4.1 未分组的「＋」卡片

- 在「未分组」section 的最后固定放一张大号「＋」卡片。
- 视觉：弱边框/虚线 + 大「＋」+「新建频道」。
- 点击后打开「频道设置」的**新建模式**，并预选「未分组」。
- 「＋」卡片：
  - 不参与拖动排序；
  - 不参与搜索（搜索时隐藏）；
  - 不算进频道数量；
  - 在「全部」或「未分组」视图都显示；
  - 即使未分组为空也显示，作为持续可见的新建入口。
- 在特定分组筛选下不显示「＋」卡片；该组通过组菜单「新建频道」创建。

### 4.2 分组菜单新建

- 从某个普通分组菜单点「新建频道」时，打开「频道设置」的新建模式，并预选该分组。
- 新频道在保存后才真正创建；保存后归入该分组。
- 初始名称使用「新频道」。
- 未达到同时打开上限时，新频道默认打开；达到上限时，新频道以关闭状态创建，并提示上限。

### 4.3 新建模式的行为

- 「频道设置」新建模式不立即落盘，而是编辑一份草稿。
- 点「保存」才创建频道；直接返回或放弃则什么都不留下，不会出现空白频道。
- 保存后返回频道网格，新卡片出现。
- **不自动切换当前频道**：新建的频道可能还没配置好，不应该抢走当前对话的焦点和声音。用户回到网格后，自己点卡片切换。
- 不提供全局新建按钮；手机端底部和桌面端顶部都不放「新建频道」。

## 5. 手机端与桌面端

### 手机端

- 底部固定一个「回到消息」横条。
- 横条只做返回消息流，不放新建入口。
- 左上角关闭按钮保留。
- 底部横条和左上角关闭是同一个动作的两个入口。

### 桌面端

- 不显示底部「回到消息」横条。
- 使用左上角关闭返回消息流。
- 新建入口使用「未分组」末尾的「＋」卡片，以及分组菜单。

## 6. 设置页与频道设置

### 设置页

- 「档案」tab 退役。
- 设置页改为单页「设置」，不再保留只有一个 tab 的 TabBar。
- 只保留通用配置：断句参数、声纹、音量键、语言、权限等。

### 频道设置页

- 独立页面，标题「频道设置」。
- 新建模式：草稿，保存才创建；预选来源分组。
- 编辑模式：从频道卡片菜单进入，加载现有频道。
- 保留现有编辑能力：名称、头像、主题色、Brain 地址/ID/token、所属分组、启用开关、历史清理、删除频道。
- 有明确的「保存」按钮；返回时如有未保存修改，弹确认框，确认后丢弃草稿/修改。
- 删除频道后返回频道网格。

## 7. 空态与数量

- 频道数量统计不包含「＋」卡片。
- 「全部」视图即使未分组为空，也显示「未分组」section 和「＋」卡片。
- 搜索时只显示匹配频道，不显示「＋」卡片。
- 新建频道受同时打开上限约束。

## 7.1 切换频道后的消息定位

- 切换到另一个当前频道后，消息流必须定位到该频道历史的最底部，不能沿用上一个频道的滚动位置。
- 历史是异步加载的：加载完成后要再次校正到底部，避免“先跳到底部、新历史又插进来”停在中间。
- 只是打开再关闭频道网格、没有切换频道时，保留原来的消息滚动位置。
- 用户主动往上翻历史时，后台新消息仍然不强制拉回底部；这是现有行为，不变。
- 新建频道没有历史时，底部就是顶部，显示空态即可。

## 8. 已按最小惊讶原则确定

1. **未分组是系统收件箱，不是普通分组。**
   - 它不是用户创建的，给完整分组菜单会让人误以为可以改名/删除。
2. **新建频道不自动切焦点。**
   - 新频道可能还没配置好，自动切过去会打断当前正在进行的对话。
3. **新建走草稿，保存才落盘。**
   - 用户点新建后又返回，不应该留下一个空白频道。
4. **设置页不保留单 tab。**
   - 只剩通用配置后，单 tab 的 TabBar 没有意义。
5. **新建入口只在未分组「＋」卡片和普通分组菜单。**
   - 不额外加全局按钮，减少重复入口。

## 9. 实施拆分

1. 术语与文案：频道 / 新建频道 / 频道设置 / 回到消息；移除用户可见的“档案 / profile”。
2. 设置页退役「档案」tab，改成单页「设置」；拆出独立的「频道设置」页面（新建草稿 + 编辑现有频道）。
3. 未分组「＋」卡片、普通分组菜单「新建频道」、保存后的归组与返回。
4. 手机端底部「回到消息」横条；桌面端只保留左上角关闭。
5. 切换频道后消息流定位到底部；历史异步加载完成后再次校正。
6. 消息气泡文本支持选择/复制，手机长按和桌面右键都能弹出复制菜单。
7. 测试：新建草稿/保存/放弃、归组、设置页、空态、搜索隐藏、计数、切换频道到底部、消息选择/复制、手机/桌面差异。

## 10. 附加小问题（与频道重构一起做）

1. **切换频道后消息流定位到底部**
   - 从频道网格切到另一个频道后，消息流应显示该频道最新一条，而不是停在顶部或沿用上一个频道的位置。
   - 历史异步加载完成后再次校正到底部。
   - 只是打开/关闭频道网格、没有切换频道时，保留原滚动位置。

2. **消息气泡文本可选择、可复制**
   - 手机端长按消息文本进入选择，使用系统选择手柄和上下文菜单。
   - 桌面端支持拖选和右键菜单复制。
   - 选择文本不能破坏消息流滚动、频道切换和历史加载。
